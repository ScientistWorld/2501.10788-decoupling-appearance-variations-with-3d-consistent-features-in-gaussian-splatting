# Scientist Constraints

## Data

Use the deterministic procedural benchmark generated by `data/synthetic_glav.py` with the same train/test view IDs and the same left-half adaptation, right-half evaluation protocol. Do not add external images, extra views, or labels. The paper's claim concerns appearance handling, so changing the dataset would make score gains incomparable.

## Scene Scale

Use the same image resolution, camera set, and initial sparse point cloud unless a submitted method explicitly reports a separate experiment name. For `synthetic_glav_core`, increasing point count, resolution, or number of views is resource scaling rather than a methodological improvement.

## Evaluation

Report scores only through `scripts/evaluate.sh`, which reads saved prediction artifacts. Do not write metrics directly into `scoring/scores.json`, and do not evaluate on the left half used for test-time appearance fitting.

## Ablations

For `synthetic_glav_ablation`, keep the same optimizer budget, training views, adaptation protocol, and scene scale as `synthetic_glav_core`. Only the single declared experimental variant should change; otherwise the result is not comparable.

## Cell Size Sweep

For `synthetic_glav_cell_size`, keep the same optimizer budget, training views, adaptation protocol, scene scale, and appearance module settings. Only the query cell size should change. Compare query cost through `cell_queries_per_view`, not wall-clock runtime.

## Compliance Checklist

- [ ] Uses the fixed procedural scene from `data/synthetic_glav.py`
- [ ] Uses the provided train and test view split
- [ ] Adapts test-view appearance only on the left half
- [ ] Reports metrics only on the held-out right half
- [ ] Uses `scripts/evaluate.sh` to produce `scoring/scores.json`
